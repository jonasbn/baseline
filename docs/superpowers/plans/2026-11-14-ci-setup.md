# CI Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `baseline` automated build/vet/test/lint coverage on every PR and push to `main`, after first clearing the pre-existing static-analysis findings that would otherwise make the new CI go red on its first run.

**Architecture:** Two sequential PRs against `jonasbn/baseline`. PR 1 (branch `fix/pre-existing-lint-findings`) fixes the `go vet`, `golangci-lint` (errcheck), and `markdownlint` findings that already exist on `main`, verified locally since no CI exists yet to check them. PR 2 (branch `ci/add-github-actions-workflow`, opened only after PR 1 is merged) adds `.github/workflows/ci.yml` (three jobs: `test` matrix, `lint`, `markdownlint`) and a `github-actions` entry in `.github/dependabot.yml`; its first CI run should be green.

**Tech Stack:** Go 1.25.1, GitHub Actions, golangci-lint v2, markdownlint-cli2.

**Spec:** `docs/superpowers/specs/2026-11-14-ci-setup-design.md`

## Global Constraints

- Go version is `1.25.1`, pinned in `go.mod` — the workflow must read it via `go-version-file`, never hardcode a version.
- `.markdownlint.json` already exists and disables several default rules — the markdownlint job must run against it, not a bare default config.
- No release automation, no Windows runner, no coverage reporting/badges, no branch-protection changes — all explicitly out of scope (tracked separately for release automation in [issue #8](https://github.com/jonasbn/baseline/issues/8)).
- PR 2 (the CI workflow) must not be opened until PR 1 (the fixes) has merged into `main` — otherwise its first run is red on pre-existing issues, defeating the point.

## Review Focus

- **A fix changes behavior, not just silences a linter.** Each errcheck fix must discard the error exactly as before (best-effort cleanup / defer close), not introduce new error handling that could change control flow — reviewed in Task 1's steps.
- **The realigned `README.md` table still renders correctly and keeps its original content.** Verified by both `markdownlint-cli2` passing and a visual diff check in Task 2.
- **The lint job doesn't silently pass on misconfiguration.** golangci-lint must actually run against the repo (not report 0 issues because it found no files) — verified by the real local run already done in Task 1, and by the PR 2 CI run itself in Task 7.
- **The matrix job must actually run on both OSes, not just syntactically define them.** Verified by checking `gh pr checks` lists two separate `test` check runs in Task 7.
- **PR 2 is opened against a `main` that already has PR 1's fixes**, or its first CI run will be red for reasons unrelated to the new workflow — enforced by Task 4's explicit branch-base step.

- [ ] **Step 4: Fix the 5 `errcheck` findings**

In `internal/sources/bitbucket/bitbucket.go:137`, where `resp` is never reassigned later in the function, change:

```go
defer resp.Body.Close()
```

to:

```go
defer func() { _ = resp.Body.Close() }()
```

In `internal/sources/github/github.go:93` and `:113`, `resp` **is** reassigned later (the 404 fallback request at line 109 overwrites it). A closure over `resp` reads it at execution time, not at the `defer` statement, so it would close the wrong response's body (or both defers would close the same, final `resp`, leaking the first body and potentially nil-panicking if the fallback request errors). Pass `resp` as an argument instead, so it's captured at the point of the `defer`:

```go
defer func(r *http.Response) { _ = r.Body.Close() }(resp)
```

(caught by a Copilot review comment on PR #9 after the original fix was committed — see the ledger for this task)

In `internal/git/git.go:118`, change:

```go
        g.setReadOnlyPermissions(repoPath)
```

to:

```go
        _ = g.setReadOnlyPermissions(repoPath)
```

(this is already inside a best-effort cleanup branch after `cmd.Run()` failed — the discarded error is intentional, just make it explicit)

In `internal/git/git_test.go:82`, change:

```go
    defer gitOps.setWritePermissions(tempDir)
```

to:

```go
    defer func() { _ = gitOps.setWritePermissions(tempDir) }()
```

- [ ] **Step 2: Create `.github/workflows/ci.yml` with the `test` job**

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

permissions:
  contents: read

jobs:
  test:
    name: Build & Test (${{ matrix.os }})
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, macos-latest]
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: actions/setup-go@b7ad1dad31e06c5925ef5d2fc7ad053ef454303e # v7.0.0
        with:
          go-version-file: go.mod
      - run: go build ./...
      - run: go vet ./...
      - run: go test ./... -race
```

## Task 7: Add `github-actions` to Dependabot config

**Files:**

- Modify: `.github/dependabot.yml`

**Interfaces:** None — additive config, independent of the workflow jobs.

- [ ] **Step 1: Add a `github-actions` entry**

Append under `updates:`, matching the existing `gomod` entry's quoting style (double quotes). Unlike `gomod` (single `minor-and-patch` group, majors left ungrouped), `github-actions` uses two groups — `major-updates` and `minor-and-patch` — so that coordinated action major bumps (e.g. `actions/upload-artifact` and `actions/download-artifact`) land together instead of as separate individual PRs:

```yaml
  # Keep GitHub Actions up to date
  - package-ecosystem: "github-actions"
    directory: "/"
    schedule:
      interval: "weekly"
    groups:
      major-updates:
        patterns:
          - "*"
        update-types:
          - "major"
      minor-and-patch:
        patterns:
          - "*"
        update-types:
          - "minor"
          - "patch"
    cooldown:
      default-days: 7
```

Run: `python3 -c 'import yaml; yaml.safe_load(open(".github/dependabot.yml"))'`
